# Candidata v1.11.1

Atualização compatível de segurança e operação preparada em 25/10/2026 (UTC).
Esta página não declara deploy nem publicação concluídos.

## Conjunto

- PR #225: registros da publicação anterior.
- PR #226: runbook, playbook e correções dos procedimentos de backup/rollback.
- PR #227: automação opt-in de backup com Restic, restore isolado e retenção
  simulada por padrão. Não instalar ou ativar timer/limpeza durante esta release.
- PR #228: origem assinada do servidor web para preservar cotas de autenticação.
- Sessão em cookie é implementada no PR #11 do repositório FinanceBot-FrontEnd;
  sua publicação precisa ocorrer depois do backend compatível/configurado.

Nenhuma migration nova desde v1.11.0. Não alterar chaves JWT/dados, hashes de senha,
preferências financeiras, volumes ou filas. Não há par público/privado JWT novo.

## Preparação e ordem

1. Verificar backup pontual cifrado, cópia fora do host e restore isolado, preservando
   o chaveiro. A #220 continua aberta até haver destino externo e rotina contínua.
2. Configurar FINANCEBOT_WEB_PROXY_SECRET exclusiva nos dois runtimes privados,
   além das origens HTTPS no frontend. Não versionar valores. Publicar API primeiro.
3. Acompanhar CI/deploy do SHA exato da promoção; validar saúde, versão, portas e
   operação do bot. O serviço de backup opt-in não deve ser ativado implicitamente.
4. Publicar o frontend depois da compatibilidade. Conferir cookie/CSRF/logout,
   ausência de JWT em JSON/Web Storage e cotas por IP, com dados de teste autorizados.
5. Criar tag/release no SHA validado e reconciliar os registros com o resultado real.

Usuários web precisarão entrar novamente. Logout remove o cookie e não revoga
cópias já roubadas do JWT. Restauração/rollback de produção exigem avaliação própria;
seguir o playbook, sem editar migrations nem retornar silenciosamente ao Web Storage.
