# v1.13.0 — Sessões revogáveis

## Novidades e segurança

Logout revoga a sessão na API, invalidando seus access e refresh tokens e preservando
outros logins. Access tokens duram no máximo 15 minutos; refresh tokens opacos de
256 bits são rotacionados e armazenados somente como SHA-256. Reutilização de um
refresh consumido revoga a sessão inteira. Sessões duram no máximo 8 horas.

Após 1 hora sem interação, o frontend mostra “Você será desconectado”, uma contagem
de 60 segundos, “Continuar conectado” e “Sair agora”. A API também impõe esse prazo.
Timers, refresh e foco não contam como atividade. Abas compartilham atividade e
logout sem expor tokens. Renovação concorrente usa Web Locks quando disponível.

Senhas permanecem com BCrypt e JWT com HMAC. Nenhum segredo novo é necessário.
Cookies de access e refresh são HttpOnly, host-only, Secure em produção e
SameSite=Lax; JavaScript não recebe as credenciais.

## Operação e compatibilidade

- Migration nova V18 cria sessões e histórico de refresh, com limpeza diária.
- JWTs anteriores sem `sid` são rejeitados: usuários precisam entrar novamente.
- Publicar a API antes do frontend compatível. `JWT_EXPIRATION=900000` explicita
  o novo limite; configurações antigas maiores também são limitadas a 15 minutos.
- Falha de revogação retorna erro e mantém o cookie para nova tentativa de logout.
- Sem Web Locks, uma corrida de refresh entre abas pode exigir novo login.
- Rollback não desfaz a migration. Não editar migrations, executar repair ou voltar
  ao armazenamento de tokens em Web Storage como recuperação automática.

Contrato completo em [sessão web](../security/web-session.md). Frontend no
[FinanceBot-FrontEnd](https://github.com/BryanPinheiro77/FinanceBot-FrontEnd).

## Validação local

- API: `./mvnw verify`, 582 testes, zero falhas/erros, com PostgreSQL, Redis e RabbitMQ
  descartáveis via Testcontainers. Neste Mac foi necessário selecionar o socket do
  Colima e carregar o agente Mockito explicitamente; sem alteração do build do projeto.
- Frontend: 33 testes, typecheck e build aprovados; 8 testes de sessão no navegador,
  incluindo refresh no reload, concorrência entre abas, CSRF e logout por ociosidade.
- Aviso inspecionado em desktop e celular, incluindo foco por teclado.
- Deploy e CI devem ser confirmados para o SHA promovido antes de declarar a versão
  publicada. Esta seção registra testes locais, sem alegar smoke com dados de produção.
